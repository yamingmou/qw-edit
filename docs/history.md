## 2026-09-19 · 起因

在千问办公里发错消息，改不了、撤不回。当晚 22:26 提了条反馈，顺手写明退出条件：**官方什么时候更新，这个项目就停止维护并归档。**

当天建仓，第一版 `0.1.0`：CDP 注入 + 用户消息悬停挂「编辑重发」。用的是最朴素的做法 —— 调 `rollbackToMessage` 截断，原文填回输入框。

## 2026-09-20 · 两天里踩的坑

- **上游被强推过**：远端 history 被改，用 `git diff` 确认内容一致后才 rebase 叠上去，没有 force 覆盖
- **按钮文字消失 bug**：`finally` 把按钮 `textContent` 重置成单字符 `"✎"`，点过一次文字就没了
- 把「重新生成」做成图标贴进官方按钮行（复制 / 满意 / 不满意那一排），而不是自己漂在外面
- 加**询问式接管**：客户端没带调试端口时不擅自重启，弹框问「是否重启加载」——把选择权交给用户

## 2026-09-22 ~ 09-23 · 会话删除与回收站

发现客户端内部有完整的回收站体系（`delete` → `listDeleted` → `restoreDeleted` → `permanentDelete` → `emptyTrash`），只是 UI 没给入口。于是补上：侧边栏悬停 🗑、顶部回收站弹窗、批量识别测试会话。

期间发现两个真 bug：
- 锁的 **TOCTOU 竞态**（两个 daemon 同毫秒启动，都过了锁检查）→ 改 `O_CREAT|O_EXCL` 原子创建
- `install` 的 **bootout→bootstrap 竞态**（launchd 还没拆干净就 bootstrap，返回 5）→ 加退避重试

## 2026-10 · 最难的一段：让撤回「真的撤回」

用户指出：**撤回只在界面生效，模型上下文没动**。

这是整个项目最重要的一次认知修正。顺着查下去：

1. 客户端内部有 `forkSession(sessionId, { upToMessageId})` —— 官方分叉原语，实测分叉出的转录文件从 955 行截到 6 行，文件级真截断
2. 但 fork 会**重映射所有消息 uuid**，导致当前会话后续的锚点全部失效 —— 所以不采用"重指会话到分支"
3. 改用 **REBUILD**：截断投影 → 会话指向全新 sessionId → 客户端下次发送时**自己从截断后的投影重建转录**。被撤回的内容按构造不可能进入上下文
4. 关键顺序：**先截断投影、后重指**。反过来的话，客户端 resume 时发现投影比转录"多"，会把缺失历史**注入 prompt**——正好把撤回的内容塞回去

这段过程里最险的一次：我把 `sdkMessageUuid` 当唯一钥匙，但实测投影的 uuid 和转录行的 uuid 是**两套互不对应的 ID**，且同一助手消息在转录里占多行。最后改用**序数对齐**（投影第 N 条助手消息 = 转录第 N 组 assistant 行）+ 文本软校验，宁停不错。

## 2026-10-20 · 性能：我自己的代码是卡顿元凶

用户报「用着卡」。一轮排查下来（A/B 摘除注入、CPU 火焰图、消融实验），真凶是**我自己的挂载循环**：

- 定时全量扫描 1.5 秒一次，每次都检查所有气泡
- React 重渲染把按钮抹掉 → 下一轮又重贴 → 每次重贴触发布局
- 两者互撕，长会话滚动时炸出成倍主线程阻塞

火焰图实测 `mountButton` 独占打开阶段 80% 非空闲时间。改成 `MutationObserver` + `requestIdleCallback` 后：长任务 16→4 次、总阻塞 2494→943ms、帧间隔 p95 56→19ms，功能零损失。

**这一段的价值不是修好了性能，是证明了"先怀疑自己"。** 前一轮我做的 A/B 全在空闲期测，测不出问题 —— 因为空闲期没有 DOM 变化，我的循环空转。是用户说"别的软件同时开都不卡"，才把我推回正确的方向。

## 2026-10-29 ~ 11-03 · 1.4.0：两个"假装成功"

1.4.0 换了两处，两处都让工具**看起来正常、实际没工作**：

- **新引擎不写回退锚点**：中间消息的截断"只截界面不截模型"，是假撤回。→ 诚实拒绝，不删任何东西
- **自定义富文本输入框**：程序写进去的文本只是视觉假象，内部模型没收到。→ 草稿改在工具自己的弹窗里，确认后走官方 API 直提

第二个坑骗了我很久：自动化测试显示"发送成功"，实际一个字都没发出去，还留下一堆空壳会话。

这一段定下了整个项目最重要的一条规矩：

> **宁可失败，也不要静默半成功。**

## 2026-11-25 · 收尾

打开客户端 2.1.0，发现官方早把这几件事都做了：重新编辑、重新生成、派生任务、删除到回收站。

>
> 本轮上下文无法安全回退，已保留原结果。
