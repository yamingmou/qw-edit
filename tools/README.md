# tools/ — 开发期验证脚本

这些是开发过程中写的临时脚本，**不是产品代码**，也不进 npm 包（`package.json` 的 `files` 只含 `bin/` 与 `src/`）。

保留它们的原因：**它们是这段开发过程唯一的原始痕迹** —— 每一次「我以为好了」和「其实没好」，都是靠这些脚本抓出来的。删掉容易，但那种"当时到底怎么想的、怎么验的"就没了。

## 分类

| 前缀 | 用途 |
|---|---|
| `probe-*` / `diag-*` | 只读探针：查数据形状、DOM 结构、接口是否存在（不改任何状态） |
| `test-*` / `e2e-*` / `regress-*` | 端到端回归：真实建会话、发消息、点按钮、验结果 |
| `qw-*` | 性能与卡顿取证：CPU 火焰图、像素 diff、空闲采样 |
| `check-*` | 版本兼容体检（1.5.0、部署状态等） |
| `out-*` | 上面那些脚本跑出来的产物（截图、JSON 快照、日志） |

## 注意

脚本里的工作目录已脱敏为 `process.env.QW_CWD || "/path/to/your/workspace"`，原始版本写死了作者的本地路径。要用的话设一下环境变量：

```bash
export QW_CWD=/path/to/your/workspace
```

大部分脚本要求客户端以调试端口运行（`--remote-debugging-port=9222`），且**会真实操作会话数据**。在用的客户端上跑之前想清楚，别拿正在干活的会话做实验 —— 这条是血的教训。
